01 · Marco de Calidad

Normas ISO aplicables

No como certificación inmediata — como marco que estructura cómo trabajamos desde hoy y es auditable desde el primer proyecto.

💡
El principio: las ISOs le dan nombre formal, estructura medible y trazabilidad auditable a lo que el equipo ya hace bien. No son trabajo extra — son el estándar que formaliza las prácticas actuales.
01

ISO 9001 · Gestión de la calidad

ISO 9001:2015Sistema de Gestión de la CalidadImplementando

Qué exige: procesos documentados, revisados y medibles. Que el cliente reciba consistentemente lo que se prometió. Que los problemas se detecten antes de llegar al cliente.

Cláusula 7.5 — Info documentadadocs/ con encabezado ISO, control de versiones e historial. La estructura de carpetas numeradas cumple exactamente este requisito.
Cláusula 8.3 — Diseño y desarrolloADRs para decisiones de diseño. Ciclo de ticket con criterios de aceptación como proceso de desarrollo controlado.
Cláusula 10.2 — No conformidadesCiclo BUG/INC → KB: detectar, investigar, corregir, aprender, prevenir.

Brecha a cerrar: formalizar objetivos de calidad medibles (% entregas sin regresiones, tiempo de resolución de incidentes) y revisión periódica del sistema.

02

ISO/IEC 27001 · Seguridad de la información

ISO/IEC 27001:2022Seguridad de la InformaciónEn progreso

Qué exige: identificar activos de información, clasificarlos por criticidad y tener controles documentados para protegerlos.

Controles implementados — aplicación (.NET 9):

A.8 — Control de activosData Protection API con claves en Vault. JWT con claims mínimos (principio de mínimo privilegio). Detección de robo de refresh token.
A.9 — Control de accesoRate limiting nativo .NET 9 por endpoint, por usuario y por IP. Validación de inputs en la frontera. BCrypt/PBKDF2 para credenciales.

Controles implementados — infraestructura:

A.13 — Seguridad de redes (Nginx)Headers hardened: HSTS, CSP, X-Frame-Options, Permissions-Policy. Rate limiting por IP. SSL/TLS con Certbot.
A.12 — Seguridad operacionalfail2ban (servidor simple) o CrowdSec (multi-servidor / ISO formal) según el proyecto. SonarQube + OWASP Dep-Check en CI/CD.
A.10 — CriptografíaHashiCorp Vault para secretos en producción. dotnet user-secrets en desarrollo. GitGuardian detecta automáticamente leaks de credenciales en el repositorio.
A.16 — Gestión de incidentesCiclo INC → KB documenta cada incidente. 12-security/vulnerabilities.md registra vectores conocidos y mitigaciones activas.
⚠️
Brechas a cerrar: inventario formal de activos de información por proyecto (qué datos se procesan, clasificación público/interno/confidencial), y el proceso de revocación de accesos y rotación de secretos cuando un desarrollador sale del equipo.
03

ISO/IEC 90003 · Ingeniería de software

ISO/IEC 90003:2018Guía ISO 9001 para softwareImplementando

Qué es: la guía oficial de cómo aplicar ISO 9001 a desarrollo de software. Define qué significa documentar el diseño, verificar y validar en el contexto de un equipo técnico.

Alineación actual: ADRs (diseño), ciclo de ticket (gestión de cambios), code review (verificación), QA independiente (validación), Git (control de versiones), docs/ (información documentada).

04

ISO/IEC 25010 · Calidad del producto

ISO/IEC 25010:2023Modelo de calidad del productoReferencia activa

Qué define: las características que debe tener un producto de software de calidad. Funciona como criterio técnico para evaluar cada entrega.

CaracterísticaCómo se mideHerramienta
Eficiencia de rendimientoTiempo de respuesta bajo carga realNBomber / k6. EXPLAIN ANALYZE.
SeguridadControles documentados y verificadosSonarQube, fail2ban/CrowdSec, OWASP Dep-Check.
MantenibilidadModificable sin introducir regresionesClean Architecture. Tests de regresión. ADRs.
ConfiabilidadOperación continua sin fallosHealth endpoints. Runbooks. Grafana + alertas.
PortabilidadMovible a otro entorno sin cambios de códigoDocker. Variables de entorno. Sin secrets en código.
Adecuación funcionalHace lo que el cliente necesitaCriterios de aceptación por ticket. QA independiente.
05

ISO/IEC 12207 · Ciclo de vida del software

ISO/IEC 12207:2017Procesos del ciclo de vidaReferencia futura

Define los procesos completos del ciclo de vida del software. El sistema actual es compatible. Se formaliza cuando el equipo crezca o cuando un cliente lo exija como requisito contractual.
