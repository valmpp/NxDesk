03 · Stack & Herramientas

El stack completo del equipo

Herramientas de pago y open source, organizadas por categoría. Cada una está aquí porque resuelve un problema concreto.

✅
Criterio de selección: si hay open source que resuelve el mismo problema igual de bien, se elige el open source. Si la herramienta de pago reduce fricción o riesgo operativo significativamente, se justifica el costo.
01

Backend — .NET 9 / C#

Core — obligatorio en todo proyecto
⚙️
.NET 9 / ASP.NET Core Open source
.NET 9 trae mejoras de rendimiento en HTTP/3, mejor soporte AOT (Ahead-of-Time compilation) y OpenAPI built-in nativo. Web API, Minimal API, Background Services, Workers. El OpenAPI integrado de .NET 9 elimina la necesidad de Swashbuckle en la mayoría de escenarios.
🗄️
Dapper Open source
Micro-ORM sobre ADO.NET. Elegido sobre EF Core para control total de queries SQL. En tablas con alta concurrencia o millones de registros, EF genera joins innecesarios que multiplican el tiempo de respuesta.
🔐
Data Protection API (.NET 9) Open source
.NET 9 refuerza la Data Protection API con soporte nativo para almacenar claves en HashiCorp Vault o Azure Key Vault, y rotación automática configurable por proyecto. Cifrado de cookies de sesión, tokens CSRF y datos PII en reposo.
🎫
JWT + Refresh Tokens con revocación Open source
Access token de vida corta (15 min). Refresh token con hash en BD y registro de rotación. Detección de robo de token: si un refresh token se usa dos veces, se revoca toda la familia de tokens del usuario.
📄
Scalar Open source Reemplaza Swagger UI
Documentación moderna de APIs OpenAPI. Integración nativa con el nuevo app.MapOpenApi() de .NET 9. UI más limpia que Swagger UI, mejor experiencia de prueba de endpoints, soporte para múltiples versiones de API y autenticación integrada en la interfaz. Sin necesidad de Swashbuckle.
⏱️
Rate Limiting integrado (.NET 9) Open source
.NET 9 incluye rate limiting nativo en el pipeline de ASP.NET Core: fixed window, sliding window, concurrency y token bucket. Configurable por endpoint, por usuario autenticado y por IP. No requiere middleware externo para el caso base.
📋
Serilog + Seq Open source Seq: pago en cloud
Logging estructurado: userId, operationId, traceId, clientId en cada log. Seq self-hosteable. Los logs son la primera herramienta de diagnóstico en producción y parte del modelo de observabilidad documentado en 07-operations/monitoring.md.
Testing backend
🧪
xUnit Open source
Framework de tests unitarios e integración estándar del ecosistema .NET. Tests de dominio, aplicación y repositorios.
🎭
Moq Open source
Mocking para tests unitarios. Aísla dependencias y prueba lógica de negocio sin base de datos real.
📊
NBomber / k6 Open source
Load testing antes de cada despliegue a producción. NBomber para integración nativa .NET; k6 para scripts más flexibles. Directamente relacionado con ISO 25010 (eficiencia de rendimiento).
02

Frontend — Blazor (.NET 9)

🎨
Blazor Server + WASM Hybrid (.NET 9) Open source
Server para supervisores (estado en servidor, conexión SignalR). WASM para clientes externos (sin conexión permanente). Un solo lenguaje en todo el stack — los desarrolladores backend contribuyen al frontend sin cambiar de contexto.
🧩
MudBlazor / Radzen Open source
Librería de componentes. Se elige una por proyecto. La librería compartida entre proyectos acelera el arranque de nuevos clientes.
⚡
Virtualize (built-in Blazor) Open source
Obligatorio en cualquier lista con más de 100 elementos. Sin virtualización el navegador colapsa con datos reales de producción. No negociable.
🧪
bUnit + Playwright Open source
bUnit para tests de componentes Blazor sin browser real. Playwright para E2E en Chromium, Firefox y WebKit.
03

Base de datos

🐘
PostgreSQL 16 Open source
Principal. FDW, particionamiento con pg_partman, alta concurrencia. Elegido sobre SQL Server por licenciamiento y rendimiento en el tipo de carga de los proyectos del equipo.
📦
Npgsql + Dapper Open source
Driver .NET para PostgreSQL y micro-ORM. Pool de conexiones gestionado, tipos específicos de PostgreSQL, queries explícitas y optimizables con EXPLAIN ANALYZE.
⚡
Redis Open source
Caché en memoria y pub/sub. Se añade cuando el perfil de carga justifica respuestas sub-10ms en lecturas frecuentes. La decisión de incluirlo se documenta como ADR.
04

Infraestructura & DevOps

🐳
Docker + Docker Compose Open source
Contenedorización completa. Dockerfile multi-stage para imágenes optimizadas en producción. Compose para el stack completo en desarrollo y staging.
🌐
Nginx Open source
Proxy inverso hacia los contenedores .NET. Terminación SSL, headers hardened (HSTS, CSP, X-Frame-Options, Permissions-Policy), rate limiting por IP en endpoints sensibles, compresión gzip. Primera línea de defensa del perímetro.
🔑
Certbot / Let's Encrypt Open source
Certificados SSL/TLS con renovación automática. Sin excusas para HTTP en cualquier ambiente accesible desde el exterior.
📊
Grafana + Loki + Prometheus Open source
Stack de observabilidad completo self-hosteable. Prometheus recolecta métricas (latencia, error rate, uso de recursos). Loki centraliza logs. Grafana visualiza dashboards con alertas configuradas.
⚙️
GitHub Actions / GitLab CI Open source self-hosted
CI/CD integrado. Pipeline: build → test → SonarQube → deploy. El pipeline no aprueba si algún test falla o si SonarQube detecta issues críticos de seguridad.
05

🔒 Seguridad — modelo por capas

🛡️
La seguridad no es una feature — es una propiedad del sistema. Cada capa tiene su responsabilidad. Si una falla, la siguiente la contiene. Este es el modelo que documenta 12-security/ en cada proyecto.

Capa 1 — Aplicación (.NET 9)

🔐
Data Protection API (.NET 9) Open source
Cifrado de datos sensibles en reposo. .NET 9 agrega soporte nativo para almacenar las claves en HashiCorp Vault con rotación automática. Cubre cookies de sesión, tokens CSRF y campos PII en BD.
🎫
JWT + detección de robo de token Open source
Access token corto (15 min) + refresh token con hash en BD. Si un refresh token se reutiliza, se revoca toda la familia de tokens del usuario — patrón de detección de robo de sesión.
⏱️
Rate limiting nativo (.NET 9) Open source
Por endpoint, por usuario autenticado y por IP. Fixed window en login y registro. Token bucket en APIs de alta frecuencia. Complementa el rate limiting de Nginx — dos capas independientes.
✅
Validación de inputs en la frontera Open source
Todo dato externo validado antes de procesar: tamaño máximo, formato esperado, detección de payloads ofuscados (base64, URL encoding, null bytes). Sin validación, no hay procesamiento.
🔒
BCrypt.Net + PBKDF2 Open source
BCrypt para passwords. PBKDF2 cuando se requiere compatibilidad con auditorías formales. Work factor documentado en ADR — ajustado al hardware del servidor y revisado en cada release mayor.

Capa 2 — Proxy (Nginx)

🌐
Headers de seguridad hardened
Strict-Transport-Security con preload. Content-Security-Policy restrictivo por proyecto. X-Frame-Options: DENY. Permissions-Policy sin acceso a cámara/micrófono/geolocalización. Referrer-Policy: strict-origin. Configuración completa en 06-infrastructure/nginx.md.
⏱️
Rate limiting en Nginx
Límites por IP en /api/auth/, /api/register y otros endpoints sensibles antes de que lleguen al servidor .NET. Primera barrera contra brute force y credential stuffing.

Capa 3 — Sistema operativo: fail2ban vs CrowdSec

📋
La elección entre fail2ban y CrowdSec se documenta como ADR en cada proyecto. No son equivalentes — tienen casos de uso distintos. La tabla de abajo define cuándo va cada uno.
fail2ban Open source
Cuándo elegirlo Servidor único. Sin requisito de cumplimiento formal. El equipo de infraestructura es pequeño y se necesita simplicidad operativa. Qué hace Lee logs de Nginx, SSH y la aplicación. Detecta patrones de ataque (brute force, escaneos) y banea la IP a nivel de iptables por tiempo configurable. Configuración documentada en 12-security/authentication.md Mantenimiento Bajo. Las reglas (jails) son archivos de texto. Sin agente central ni dashboard.
CrowdSec Open source
Cuándo elegirlo Multi-servidor. Datos sensibles de clientes. Requisito de cumplimiento formal (ISO 27001). Mayor superficie de ataque o tráfico elevado. Qué agrega vs fail2ban Inteligencia de amenazas compartida: IPs maliciosas conocidas se bloquean proactivamente antes de atacar. Múltiples bouncers (Nginx, iptables, Cloudflare). Dashboard centralizado de amenazas activas. Configuración documentada en 12-security/vulnerabilities.md Mantenimiento Medio. Agente en cada servidor. Dashboard centralizado para ver amenazas en todos los proyectos.

Capa 4 — Gestión de secretos

🔐
HashiCorp Vault Open source
Gestión centralizada de secretos. Acceso por política: cada servicio solo accede a lo que necesita. Audit log de quién accedió a qué y cuándo. Integración con Data Protection API de .NET 9 para almacenamiento de claves de cifrado. Self-hosteable.
🔒
dotnet user-secrets (desarrollo local) Open source
Para secrets en desarrollo. Nunca en appsettings.json ni en el repositorio. Staging y producción usan Vault o variables de entorno del servidor.

Capa 5 — Análisis estático y detección de leaks

🔍
SonarQube Community Open source
Análisis estático en CI/CD. Detecta vulnerabilidades OWASP, code smells y deuda técnica. El pipeline no aprueba si hay issues de seguridad críticos o altos sin resolución.
🔐
GitGuardian Pago — gratis para open source
Detecta secrets en el historial de Git: API keys, passwords, tokens — incluso en commits ya subidos. Primera defensa contra leaks de credenciales accidentales.
📋
OWASP Dependency-Check Open source
Detecta dependencias NuGet con CVE conocidas. Se ejecuta en CI/CD. Si una dependencia tiene CVE crítica, el build falla hasta que se actualice.

07

Gestión de proyectos y APIs

📋
ClickUp Pago → Linear Pago
ClickUp actual. Linear reemplaza: branch → tarea "En progreso", merge → ticket cerrado automáticamente. Trazabilidad total del commit al cliente.
🗂️
Plane Open source — self-hosted
Alternativa open source a Linear/Jira. Self-hosteable si el cliente exige que los datos de gestión estén en infraestructura propia.
📮
Bruno Open source / Postman Pago
Testing de APIs. Bruno guarda las colecciones como archivos en el repositorio — se versionan con Git. Scalar también expone un cliente de prueba integrado directamente en la documentación de la API.
📊
draw.io / diagrams.net Open source
Diagramas de arquitectura, flujos, entidad-relación. Los .drawio se guardan en 01-architecture/diagrams/ junto con el .png exportado. Integración con VS Code y Rider.
08

Automatización y RPA

🐍
Python 3.11+ Open source
Lenguaje principal para RPA y procesamiento de datos. Generadores eficientes, async, Regex avanzado, integración con PostgreSQL via psycopg2.
🌐
Playwright (Python) Open source
Automatización de navegadores para RPA web. Más robusto que Selenium en SPAs y aplicaciones modernas.
⏰
Hangfire Open source core
Scheduling de tareas recurrentes en .NET. Background jobs con dashboard visual de estado. Para automatizaciones que viven dentro del ecosistema .NET 9.
